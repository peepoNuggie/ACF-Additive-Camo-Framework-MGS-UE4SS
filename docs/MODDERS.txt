================================================================================
  ACF - Additive Camo Framework  v1.0
  Making a camo mod that targets an ACF slot
================================================================================

ACF gives you four new camouflage slots. Your mod fills one of them, and the
player keeps every vanilla camo.


--------------------------------------------------------------------------------
THE SHORT VERSION
--------------------------------------------------------------------------------

Ship a CamouflageAssetType asset named Camouf_<ID>_asset at

    /Game/Maps/AssetCamouflage/Camouf_<ID>_asset

where <ID> is 61, 62, 63 or 64. That is the whole contract. ACF does the rest:
the slot is unlocked automatically, named, and given an icon.

    slot         camo ID     shown in game as
    ---------------------------------------------
    1            61          ACF Mod 1
    2            62          ACF Mod 2
    3            63          ACF Mod 3
    4            64          ACF Mod 4

There are only four. This is a hard limit of the game - those are the reserved
uniform slots it already knows about (ADDITIONAL_UNIFORM_2 through 5). Higher IDs
exist in the enum but can never be equipped: 65 is a download placeholder, 66 was
an internal sentinel, and 67 to 69 are cardboard boxes.


--------------------------------------------------------------------------------
BUILDING THE ASSET
--------------------------------------------------------------------------------

The easiest route is to clone an existing camo asset and repoint it.

1. Extract a vanilla camo asset to edit as a template:

       retoc to-legacy <game>\Content\Paks <out> --version UE5_3 -f "Camouf_12_asset"

   Camouf_12 (Sneaking Suit) is a good template because it uses both materials
   and meshes. Camouf_5 (Splitter) is material-only and simpler.

2. Open it in UAssetGUI and repoint its Import entries at your own materials and
   meshes. You do not need to touch the export/property data - the properties
   reference imports by index, so changing what an import resolves to is enough.

3. Rename it to Camouf_61_asset (or 62/63/64). Renaming needs TWO edits:

       * the Name Map entries (short name and full package path)
       * General Information -> PackageName

   Miss the PackageName and the asset keeps the original's chunk ID, which means
   it silently OVERRIDES the camo you cloned instead of becoming a new one. This
   is the single most common mistake.

4. Package it:

       repak pack <folder>
       retoc to-zen <in.pak> <out.utoc> --version UE5_3

5. Ship the resulting .pak, .ucas and .utoc together, to be placed in
   Content\Paks\mods\. All three are required.

A camo that only changes textures does not need new meshes - clone the material
instances and repoint BaseColor_NonVT at your texture.


--------------------------------------------------------------------------------
OPTIONAL: YOUR OWN THUMBNAIL
--------------------------------------------------------------------------------

Each slot draws its icon from a texture the base game already ships:

    slot 1 (61)   Plugins/CobraUI/Content/Textures/sv/camouflage/9200220
    slot 2 (62)   .../9265756
    slot 3 (63)   .../9331292
    slot 4 (64)   .../9396828

Those are 256x128 DXT5, stored inline in the .uexp with this layout:

    113 bytes header | 32768 bytes DXT5 pixel data | 28 bytes trailer

So you can swap the art without any resizing: keep the header and trailer, and
drop in the 32768 bytes that follow the 128-byte header of a 256x128 DXT5 .dds.

ACF already overrides all four with its own logo. If you override the one for
your slot, yours wins if your pak loads later - but that is load-order dependent,
so mention it in your description rather than relying on it.


--------------------------------------------------------------------------------
CHECK YOUR CHUNK ID
--------------------------------------------------------------------------------

IoStore finds assets by a hash of the package path, not by filename. If yours
does not match what the game expects, the pak mounts and does nothing at all -
no error, no warning.

For a NEW asset (Camouf_61_asset), the ID must be unique - compare it against the
asset you cloned and confirm they differ:

    retoc list --path <your>.utoc

For an OVERRIDE (a thumbnail), the ID must be IDENTICAL to vanilla's:

    retoc list --path <game>\Content\Paks\pakchunk0-Windows.utoc | findstr 9200220
    retoc list --path <yours>.utoc | findstr 9200220


--------------------------------------------------------------------------------
SLOT COLLISIONS
--------------------------------------------------------------------------------

If two installed mods use the same slot, one silently disappears - last pak
loaded wins.

Please:

  * State clearly in your mod description which slot it uses.
  * Consider uploading alternate files for different slots so users can avoid
    clashes.
  * Put the slot number in the filename, e.g. MyCamo_ACF_Slot2.pak.


--------------------------------------------------------------------------------
TESTING
--------------------------------------------------------------------------------

With ACF installed, load a save and open the Survival Viewer. Your camo should
appear in its slot and be selectable immediately - no console commands.

If the slot is listed but shows Olive Drab, the asset is not resolving. Check the
name is exactly Camouf_<ID>_asset, the path is /Game/Maps/AssetCamouflage/, and
the chunk ID is unique.

UE4SS.log lines tagged [ACF] show what the framework resolved.
